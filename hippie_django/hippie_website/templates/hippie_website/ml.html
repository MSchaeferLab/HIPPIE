Key Reading

Before training a PPI predictor, read these. They explain why most reported PPI-prediction accuracies are inflated, and how to build honest evaluations.

Cracking the black box of deep sequence-based protein–protein interaction prediction Bernett J, Blumenthal DB, List M. Briefings in Bioinformatics, 2024; 25(2): bbae076. Shows that random train/test splitting leaks information; once sequence similarity between splits is minimised, deep models drop to near-random, while trivial sequence-similarity / node-degree baselines remain competitive. doi:10.1093/bib/bbae076

{# ── Workflow intro ── #}
A PPI-Prediction Workflow

Here we show a typical end-to-end example: choose data, export it from HIPPIE, build a leakage-aware train/validation/test split with the ppi-splitting-pipeline, train two contrasting models (a classic feature-based baseline and a sequence-based model), and evaluate honestly. Take this both as a tutorial if you want to start with PPI prediction and as a resource showing the pitfalls of data leakage.

{# ── Step 1 ── #}
1

How do I choose my data?

A PPI classifier needs positive examples (interacting pairs) and negative examples (non-interacting pairs). HIPPIE gives you scored positives and experimentally reported non-interactions, but the difficult part is splitting the data in a way that reduces biases and data leakage.

  • Positives — the interacting protein pairs. Higher confidence thresholds (≥ {{ current_release.int_q3|default:0.00|floatformat:2 }}, high confidence) trade quantity for reliability.
  • Negatives — there is no gold-standard "these never interact" set. HIPPIE provides curated non-interactions, but far fewer of them than positives, so most negatives have to be sampled from pairs with no known interaction. Naively sampled negatives are biased by node degree, which a model can exploit instead of learning biology.
Leakage trap: If the same protein appears in both train and test — or two near-identical sequences are split across train/test — the model can memorise per-protein or per-family signal and report inflated accuracy. Decide your split strategy before sampling negatives.
{# ── Step 2 ── #}
2

How do I get the data out of HIPPIE?

There are three routes, from least to most effort:

  • Pre-computed splits — the Download page offers finished splits of the high-confidence interactions, the high-and-medium-confidence ones, and the whole database. If one of these fits, you can skip to step 4.
  • Raw data + your own pipeline run (this tutorial) — filter HIPPIE the way you need on the ML Splits page, download the filtered data, and build the split yourself on your own machine or cluster.
  • Splits generated on the server — the ML Splits page can also run the pipeline for you. This is convenient, but jobs are queued and run one at a time. A run usually takes about 35 minutes and is stopped after {{ split_max_run }} at the latest; a filter set too large or complex for that has to go through the raw-data route instead. Because of our computational constraints the server also gives the optimisation steps a much smaller time and memory budget than a local run (30 minutes instead of 2 hours per ILP, on 2 CPUs). The resulting splits are valid but usually less well optimised than what you get locally.

For this tutorial we use the whole database. On the ML Splits page, leave every filter at its default (or narrow it — e.g. to proteins with a minimum expression in a specific tissue, from median gene-level RNA-seq of GTEx{% if current_release.gtex_version %} {{ current_release.gtex_version }}{% endif %}; see the filter guide), click Calculate statistics, then Download Raw Data. The ZIP contains:

  • ppis.csv — the filtered interactions: protein1,protein2,score (UniProt accessions, isoforms included).
  • candidate_negatives.csv — only when curated HIPPIE non-interactions match your filters: protein1,protein2,w. Negative sampling is then restricted to this pool.
  • samplesheet.csv — a ready-made one-row samplesheet for the pipeline.
  • README.txt — the filters you applied, the counts, and the exact command to run.

3

How do I build the split?

The ppi-splitting-pipeline is a Nextflow pipeline. You need:

  • Nextflow and one of Docker, Singularity, Apptainer or Conda (the pipeline ships a profile for each).
  • Internet access — protein sequences and annotations are fetched from UniProt.
  • Enough compute. The all-vs-all sequence comparison (BLAST) is the heaviest step; for the whole database a cluster is advisable (add the slurm profile).
  • Optionally a Gurobi license (free for academics). Without one, the pipeline falls back to open-source solvers.
# 1. get the pipeline next to the unzipped raw data (sibling folders)
git clone https://github.com/bionetslab/ppi-splitting-pipeline
unzip hippie_splits_<job-id>.zip -d hippie_raw_data   # the file you downloaded
cd hippie_raw_data

# 2. run it (pick the profile matching what you have installed)
nextflow run ../ppi-splitting-pipeline/main.nf \
    --samplesheet samplesheet.csv --outdir results -profile docker

# no Gurobi license? append:
#   --ilp_solver '' --gurobi_license ''

What the pipeline does with your data:

  1. Fetches the sequences and compares every protein against every other (BLAST) to build a sequence-similarity graph, which is then partitioned into clusters of similar proteins.
  2. Splits the positives into train / validation / test with an ILP that keeps similar proteins on the same side, then removes remaining homologous train/test pairs with CD-HIT-2D. Expect noticeably fewer pairs than you exported.
  3. Samples negatives with a second ILP that matches the positives' degree, taxon-pair, self-loop and GO-similarity profile (1:1), plus a separate realistic test set with uniformly sampled negatives at 1:10.
  4. Trains a small baseline classifier and writes a MultiQC report (results/multiqc/multiqc_report.html) with split sizes, bias diagnostics and similarity heatmaps.

The splits you need land in results/hippie/:

  • train.csv, val.csv, test_balanced.csv — 1:1 positives to bias-matched negatives.
  • test_realistic.csv — 1:10 with uniform negatives, simulating an uncontrolled screen.
  • Each has the columns protein1,protein2,label,score (label 1 = interacts, 0 = negative); the sequences are in results/hippie/data/sequences.fasta.
Reproducibility. The split is fixed by the pipeline's seed (a pipeline parameter, 42 by default) and its version. Note both, and publish the split files with your results.

How do I create a model with the data?

We build two models side by side: a classic feature-based baseline and a sequence-based model. Both share the same split so the comparison is fair.

Load the data 
import pandas as pd

splits = {name: pd.read_csv(f"results/hippie/{name}.csv")
          for name in ["train", "val", "test_balanced", "test_realistic"]}
train = splits["train"]
# columns: protein1, protein2, label (1 = interacts, 0 = negative), score
print(train["label"].value_counts())
A — Classic baseline (scikit-learn)

Cheap topological features straight from the interaction network. Per the first paper under Key Reading, this kind of baseline is surprisingly hard to beat — always report against it. 

# pip install scikit-learn networkx
import networkx as nx
from sklearn.ensemble import RandomForestClassifier

# build the graph from POSITIVE training edges only (no test leakage!)
G = nx.Graph()
G.add_edges_from(train[train.label == 1][["protein1", "protein2"]].itertuples(index=False))

def features(a, b):
    own = int(G.has_edge(a, b))   # don't let a training pair count its own edge
    deg_a = G.degree(a) - own if a in G else 0
    deg_b = G.degree(b) - own if b in G else 0
    common = len(list(nx.common_neighbors(G, a, b))) if a in G and b in G else 0
    return [deg_a, deg_b, deg_a * deg_b, common]

def X_base(df):
    return [features(a, b) for a, b in df[["protein1", "protein2"]].itertuples(index=False)]

clf = RandomForestClassifier(n_estimators=300, n_jobs=-1, random_state=0)
clf.fit(X_base(train), train["label"])
B — Sequence-based model

Embed each protein sequence with a protein language model (e.g. ESM-2), concatenate the pair, and train a small classifier. More expressive — and far more prone to leakage. 

# pip install torch fair-esm scikit-learn biopython
import numpy as np, torch, esm
from Bio import SeqIO
from sklearn.linear_model import LogisticRegression

# the pipeline already fetched the sequences (FASTA headers are UniProt accessions)
seqs = {r.id: str(r.seq) for r in SeqIO.parse("results/hippie/data/sequences.fasta", "fasta")}

model, alphabet = esm.pretrained.esm2_t12_35M_UR50D()
batch_converter = alphabet.get_batch_converter()
model.eval()

def embed(seq):
    _, _, toks = batch_converter([("p", seq[:1022])])   # ESM-2 context limit
    with torch.no_grad():
        out = model(toks, repr_layers=[12])["representations"][12]
    return out[0, 1:toks.shape[1] - 1].mean(0).numpy()   # mean-pooled residue embeddings

proteins = set().union(*(set(df.protein1) | set(df.protein2) for df in splits.values()))
emb = {p: embed(seqs[p]) for p in proteins}

def X_seq(df):
    return np.array([np.concatenate([emb[a], emb[b]])
                     for a, b in df[["protein1", "protein2"]].itertuples(index=False)])

seq_clf = LogisticRegression(max_iter=1000).fit(X_seq(train), train["label"])
Where leakage creeps in (second paper under Key Reading, question on data splitting). A random pair split lets the same protein sit in both train and test. The sequence model then just recognises proteins it has already seen — not interactions. A naive random split can push AUROC from ~0.6 to >0.9 of pure illusion.
Already handled. The pipeline split by sequence-similarity clusters, so near-identical proteins do not straddle train and test. Do not re-shuffle or re-split the files — tune hyperparameters on val.csv only, and touch the test sets once, at the end.
{# ── Step 5 ── #}
5

How do I evaluate this?

Score both models on both held-out test sets and always compare against the baseline. test_balanced (1:1) is comparable to most published numbers; test_realistic (1:10) is closer to how a predictor is actually used, and there AUPRC matters far more than AUROC. 

from sklearn.metrics import roc_auc_score, average_precision_score

for test_name in ["test_balanced", "test_realistic"]:
    test = splits[test_name]
    y = test["label"].to_numpy()
    for name, proba in [
        ("baseline", clf.predict_proba(X_base(test))[:, 1]),
        ("sequence", seq_clf.predict_proba(X_seq(test))[:, 1]),
    ]:
        print(f"{test_name:15s} {name:9s}  AUROC={roc_auc_score(y, proba):.3f}  "
              f"AUPRC={average_precision_score(y, proba):.3f}")
  • Beat the baseline, or report why not. If the sequence model only wins under a random split but ties the baseline under a similarity-aware split, the "win" was leakage.
  • Stratify by novelty. Report metrics separately for test proteins that are dissimilar to anything in training — that is the realistic use case.
  • Fix the seed and publish the split. Reproducibility is part of the result.

For the full reasoning behind each of these checks, see the papers under Key Reading above.
