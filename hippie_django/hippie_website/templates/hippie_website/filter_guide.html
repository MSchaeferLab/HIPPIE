{# ── How filters combine ── #}

How filters combine

The protein query, interaction query, network and browse pages share one filter panel; each page shows the subset of controls relevant to it. Hover the icon next to a filter for a short summary, and follow its More details link to the matching section of this page.

  • Filters take effect only when you run or re-apply the search.
  • Different filters combine with logical AND — a result must pass every active filter to be shown.
  • Ticks within one list (sources, experiment types, interaction types, tissues) combine with OR — a result needs to match only one ticked option.
  • The lists start with every option ticked. Clearing a list removes that filter rather than excluding everything, so an unticked list and a fully ticked one return the same results.
  • The number beside each option is counted across all of HIPPIE. It is not recomputed for the subset your other filters leave, so it does not change as you narrow the query. Options that no interaction uses are not listed at all.
  • Protein-level filters (tissue, degree, average score, review status) are checked on the proteins of each interaction. The proteins you query on the protein query page and the seeds on the network page are never removed by them — they apply to the partners that HIPPIE adds.

The same filters are available programmatically; see the REST API.

{# ── Result type ── #}

Result type

  • Interactions — experimentally supported protein pairs, each with a confidence score.
  • Non-interactions — protein pairs experimentally reported not to interact. Their rows are drawn on a grey background.
  • Both — interactions and non-interactions together.

Non-interactions carry no source database, experiment type or interaction type. As soon as one of those three lists is narrowed, non-interactions can no longer match and are left out of the result.

{# ── Confidence ── #}

Confidence score

Keeps results whose score lies between a minimum and a maximum bound (0–1); the sliders clamp so that the minimum never exceeds the maximum. How the score is computed is explained under confidence scoring.

The Medium conf. and High conf. presets set the minimum to the current release's median (Q2) and upper-quartile (Q3) score for the selected result type{% if current_release %} — for interactions currently ≥ {{ current_release.int_median|floatformat:2 }} and ≥ {{ current_release.int_q3|floatformat:2 }}{% endif %}.

{# ── Tissues ── #}

Tissue expression

Keeps interactions whose proteins are expressed in any of the ticked tissues. Expression is the median gene-level RNA-seq expression from GTEx{% if current_release.gtex_version %} {{ current_release.gtex_version }}{% endif %}. Once the tissue list is narrowed, an optional Min. median TPM raises the required expression level. Only genes reaching a median of 1.0 TPM in at least one tissue were imported, so a threshold below 1.0 has no additional effect.

Tissues are grouped by body system and then by organ. The number beside each tissue is how many genes GTEx measures as expressed there — genes, not interactions.

{# ── Protein filters ── #}

Protein filters

  • Min. degree in all of HIPPIE ≥ — the minimum number of interaction partners a protein has across the whole database.
  • Min. avg. score ≥ — the minimum mean confidence score across a protein's interactions.

Both are measured across all of HIPPIE, independently of the source, score and type filters. A protein can therefore pass a high degree threshold and still contribute only a handful of interactions to a narrowly filtered result. For the same reason the median degree in the statistics box of the ML Splits page, which counts only the interactions that survive the filters, is often much lower than the threshold.

{# ── Review status ── #}

Review status

  • Reviewed — manually curated UniProtKB/Swiss-Prot entries.
  • Unreviewed — automatically annotated UniProtKB/TrEMBL entries.
  • Both — no review-status filter.

{# ── Isoforms ── #}

Isoforms

HIPPIE stores interactions both for general protein entries (e.g. P37163) and for individual isoforms (e.g. P37163-2); see Isoforms for background. The three-way filter decides which of them are shown:

  • General — general protein entries only. An isoform still appears when you query it explicitly.
  • Isoforms — only interactions in which at least one partner is a non-canonical isoform.
  • Both — no isoform filter: general proteins and isoforms together.

{# ── ML splits page ── #}

Filters on the ML Splits page

The ML Splits page uses the same filters, arranged in two rows: protein filters (tissue expression, degree, average score, isoforms) on top and interaction filters (confidence, experiment type, interaction type, source database) below. A protein that fails the protein filters removes every interaction it takes part in. How the filtered set is turned into train / validation / test data is described in the Machine Learning guide.
